# 个人信息页设计与实施计划

日期：2026-10-03。状态：已实施并验证。用户已选择独立页面、设置与搜索头像共用入口。

## 交互与归属

设置列表第一项新增「个人信息」。首页搜索栏的头像按钮进入同一个独立页面，标签保持「个人信息」。页面展示当前用户头像和只读用户名，明确提供「更换头像」按钮；选择图片后立即保存，取消选择不改变头像。保存时禁用按钮，失败提示可被读屏发现，保留原头像并允许重试。页面可滚动并使用共享内容宽度，展示时隐藏底部导航和大屏侧栏，返回恢复发起入口及 Tab 导航。

目的地和序列化贡献属于 settings-api；页面、MVI 和文件选择/保存属于 settings。composeApp 装配导航；email 只回调宿主，不依赖 settings 实现。共享头像展示与默认图片属于 core:theme。用户名读取 UserModel.nickname，不增加编辑用户名功能。

## 实施顺序与验证

1. 先添加两个入口、返回和返回栈恢复的宿主回归测试并确认现有行为失败。
2. 接入 settings-api 目的地、设置列表操作、搜索头像导航；移除搜索中的头像保存职责。
3. 实现个人信息页与保存状态；迁移平台图片存储，唯一文件名，先持久化新头像再删除旧文件，失败清理新文件。
4. 测试保存成功、失败与取消、重复操作；验证按钮标签/禁用、用户名和大字号滚动布局。
5. Android 构建、宿主测试和 iOS 编译；同步架构与无障碍审计状态。

本次用户明确要求保留已有提交，不做 squash 或改写提交历史；当前未提交的个人信息改动通过新增提交保存。

## 验证结果

settings 宿主测试 14 项、组合根定向回归实际 22 项（跳过 45 项）、iOS 组合根 24 项和 data 模块实际 8 项（跳过 1 项）均无失败。Android 整包构建和 lint 通过，lint 0 Error / 12 Warning。候选截图已检查，独立只读代码审查未发现具体缺陷。系统图片选择器与真实读屏的人工验收尚未执行。详细修复证据见 `docs/audits/2026-10-02-accessibility.md` 第四项记录。

## 页面层级调整

用户进一步确认个人信息作为次级全屏页面展示。导航外壳以 `NavigationSuiteType.None` 隐藏导航套件，保留 Tab 返回栈和内容组合位置。新增/扩充手机和 1200×900dp 大屏回归，覆盖隐藏导航、两个入口、页面恢复、顶部返回和系统返回；17 项导航回归与 iOS 编译通过。另复验既有 Tab 切换与状态恢复，并更新模拟器安装。

## 后续模块拆分

用户确认将个人信息迁移到独立的 `feature:profile-api` / `feature:profile`。上述 settings 归属记录描述初始实现；当前目的地、入口契约与导航贡献由 profile-api 拥有，页面、MVI、头像保存及测试由 profile 拥有。settings 仅保留设置项与点击事件，composeApp 完成装配。旧目的地序列化名称保持兼容。实施与验证结果见 [模块拆分计划](../plans/2026-10-03-profile-module-split.md)。
