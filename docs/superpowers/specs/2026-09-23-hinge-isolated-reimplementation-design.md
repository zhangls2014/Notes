# 铰链适配隔离重做设计

日期：2026-09-23  
状态：待用户书面复核

## 背景

提交 `30b2ab1c` 在加入铰链安全区域的同时，改写了若干普通设备也会经过的布局、系统内边距和 Material 组件路径。结果是没有铰链的设备上也出现视觉回归，包括首页搜索框和设置页。修复目标不是继续在现有实现上逐项打补丁，而是先恢复提交前的稳定视觉基线，再以严格隔离的方式重新实现铰链支持。

## 目标

- 没有铰链时，页面组件、尺寸、间距、滚动、系统内边距和导航形态与 `30b2ab1c` 的父提交 `708ec616` 保持一致。
- 只有窗口事实明确报告至少一条可见铰链时，才启用铰链安全布局或安全弹层。
- 保留同一铰链几何在半开和全开之间的窗格、导航与交互状态稳定性。
- 覆盖登录、首页、收藏、邮件详情、搜索、写邮件、设置、设置选择器和通用确认弹窗。

## 非目标

- 不回退 `30b2ab1c` 之前已经完成的窗口事实、内容宽度或 Navigation 3 架构。
- 不借本次修复重做视觉设计、主题或信息架构。
- 不在 Feature 中引入第二套窗口断点、窗格脚手架或铰链缓存。
- 不声称模拟器无法提供的三折真机验证已经完成。

## 实施策略

### 1. 恢复稳定基线

以反向应用 `30b2ab1c` 的方式撤销该提交涉及的生产代码、测试与配套文档，恢复到 `708ec616` 的行为。撤销范围严格限定为该提交；执行前检查工作区，避免覆盖用户已有修改。

恢复后先运行与该提交影响范围相关的现有测试和编译任务，证明基线可构建，并记录任何原本就存在的问题。

### 2. 测试先行定义隔离边界

在重新加入生产代码前，先增加会失败的回归测试：

- 空铰链列表不会改变安全区域、导航策略或页面路径选择。
- 存在竖向或横向铰链时才计算安全区域。
- 同一铰链几何在半开与全开状态下产生相同的安全区域与导航决策。
- 多铰链、乱序、零宽折痕和窗口外裁剪保持确定性。

页面级分支尽量提炼成纯策略函数，以便测试“原始路径”与“铰链路径”的选择，而不依赖脆弱的像素截图作为唯一自动化证据。

### 3. 重新实现公共铰链能力

窗口事实仍只在 `composeApp` 读取，并通过 CompositionLocal 下发。`core:theme/layout` 可以提供铰链几何与安全区域原语，但必须满足：

- 空铰链时不额外包裹强制尺寸、裁剪或重测量的布局节点。
- 不改变普通路径的 WindowInsets 消费关系。
- 不在 Feature 中重新计算窗口断点。
- 使用实际窗口坐标转换，不缓存旧铰链位置。
- 竖向窗格 directive 统一使用 `HingePolicy.AlwaysAvoid`。

### 4. 按页面隔离适配

- 登录：只在存在相关铰链时按安全区域放置品牌与表单；普通设备保留原布局。
- 首页、收藏和详情：继续由 Navigation 3 场景策略装配。只有存在铰链时，宿主才增加必要的几何约束。
- 导航外壳：普通设备继续使用原 `NavigationSuiteScaffold` 和原 insets 行为；铰链设备使用稳定且避让铰链的专用路径。
- 搜索：普通设备继续使用原 `AppBarWithSearch`、`ExpandedFullScreenSearchBar` 或 `ExpandedDockedSearchBar`；铰链设备才使用安全弹层。搜索文本、展开状态和滚动状态位于分支之外。
- 写邮件：普通设备继续使用原 `ModalBottomSheet`；铰链设备才使用安全弹层，草稿和滚动状态位于分支之外。
- 设置：普通设备保留原 `Scaffold`、`AdaptiveContent` 和 Preference 组件树；只有铰链设备在不改变普通树的独立分支中使用安全区域。
- 设置选择器与通用确认：普通设备保留依赖库或 Material 的原弹窗；铰链设备才替换为安全弹层。
- Tooltip：普通设备保留原 popup；铰链设备可以降级或限制到安全区域，但保留无障碍标签。

### 5. 状态与错误处理

视觉分支不得拥有业务状态。搜索查询、搜索展开状态、列表滚动、设置选择、写邮件草稿和对话框打开状态应在分支外创建并传入。窗口几何实际改变时允许重新布局；只有折叠状态改变但几何相同时，不应重置交互状态或切换导航形态。

若平台没有报告铰链，则按普通设备处理，不尝试根据设备名称、方向或导航方位推测铰链。若设备断连导致模拟器显示参数无法恢复，必须在交付说明中明确报告。

## 验证

自动化验证串行执行，避免 Gradle 守护进程锁冲突：

1. 相关 `core:theme`、登录和主界面测试。
2. `./gradlew :androidApp:assembleDebug`。
3. `./gradlew :composeApp:compileKotlinIosSimulatorArm64`。
4. 适用时执行 Android lint。

视觉验证至少覆盖：

- 普通手机：首页搜索框、底部导航、设置列表与选择弹窗、退出确认、写邮件和登录。
- 普通宽屏/平板：侧栏、列表—详情、设置内容宽度和 docked 搜索。
- 折叠模拟器：竖向与横向铰链、半开与全开、搜索/设置弹窗和 IME。

普通设备截图与恢复基线对比，确认没有新的组件替换、额外留白、裁剪或尺寸变化。折叠设备检查所有交互内容不跨铰链，并验证相同几何下半开与全开布局一致。

若测试期间修改模拟器 `wm size` 或 `wm density`，结束前必须执行 reset 并查询确认没有 `Override`。

## 完成标准

- `30b2ab1c` 引入的普通设备视觉回归消失。
- 无铰链路径与 `708ec616` 的组件选择和布局行为一致。
- 有铰链路径满足安全区域和姿态稳定性要求。
- 自动化测试、Android 构建和 iOS 编译均有本次运行的成功证据。
- 文档与最终实现一致，未把模拟验证描述成真机验证。
