# Notes 官网 Web 模块实施计划

**目标** 在现有仓库建立 `:web`，用 Compose Multiplatform 和 Kotlin/Wasm 实现摘星官网。

**架构** 在现有 `web/` 中注册独立 Gradle 模块，官网页面由 Compose 渲染。Gradle 将 Wasm 应用与现有生成器产出的下载落地页、更新清单、按平台发布的开源声明和平台关联文件合成到 `web/dist`。公开页面沿用原有地址，由 Web 组合根恢复页面和参数。

## 实施步骤

- [x] 注册 `:web`，配置 `wasmJs { browser() }`、可执行产物和 Compose 插件。约定 `web/src/wasmJsMain/kotlin/` 存放页面、浏览器和导航代码，`web/src/wasmJsMain/resources/` 存放 HTML 入口及网站资源。为 `:core:model` 和 `:core:theme` 增加 Wasm 目标，使用仓库已有版本目录。先运行 `./gradlew :web:wasmJsBrowserDistribution`，验证编译与浏览器启动。
- [x] 实现首页、下载、更新日志和开源声明。通过 `ComposeAppTheme` 复用应用配色、字体层级、形状和图标，沿用已定稿的导航和平台图标。官网通过主线已有的 `/releases/published.json` 读取更新日志，声明入口集中在独立页面。宽屏使用版本列表与详情窗格，窄屏显示单窗格；用 Navigation 3 管理页面并单独接浏览器历史。保留公开路由、平台查询参数和版本锚点，验证直接访问、刷新及前进后退。
- [x] 复用 `AppLanguage`、`DarkThemeConfig`、`FontSizeConfig`，接浏览器语言、系统主题和本地偏好。验证切换即时生效，刷新后恢复，并兼容已有 App 外观与嵌入参数。
- [x] 将 Wasm 入口和资源与现有生成器输出合成到 `web/dist`。原有下载落地页、版本清单、按平台发布的开源声明、`.well-known` 文件和响应头规则继续由现有逻辑生成。首次交付提供本地预览与构建说明。
- [x] 运行 `node --test web/build.test.mjs` 和完整网站构建。Chrome 验证四页加载、宽窄窗格、平台选择、浏览器前进后退及偏好刷新恢复。共享模型和主题完成 Android / iOS 编译。使用测试配置对比下载落地页、更新清单、按平台发布的开源声明和关联文件。Chrome 禁用 WebAssembly 后，HTML 下载入口仍可用。
- [ ] 验收 Safari、键盘导航及正式服务器的 Wasm MIME 类型。

首版以支持 WasmGC 的浏览器为目标。后台、账号功能及生产部署分别规划。
