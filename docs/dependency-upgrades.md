# 依赖与工具链升级规范

Notes 是功能验证项目，升级目标是采用满足现有功能、平台要求且能通过项目回归的官方支持范围内的最新兼容版本。正式版优先；本规范适用于以后每次依赖、编译器、构建工具和平台配置升级。

## 版本选择

1. 优先选择核对当天已发布的最新兼容正式版；不主动追 EAP、alpha、beta、RC、snapshot 或 nightly。
2. 当前已使用预览版的组件，检查正式版能否提供项目正在使用的 API 和功能。能满足时迁移到正式版；不能满足时保留必要的预览版并记录具体原因，不移除功能来追求全正式版。
3. 最新正式版存在已确认的不兼容时，采用最近兼容正式版，记录阻碍升级的插件、API、平台或验证失败。不要靠关闭检查、忽略异常或注释代码使升级通过。
4. 不把版本号最大当作整套组合兼容。先核对官方兼容表、发布说明、仓库元数据和平台工件，再做项目实测。官方明确的支持范围和最高测试版本作为升级上限，取相关工具约束的交集；不因本机安装了更新版本或项目实测通过而越过上限。官方表中的最低版本、默认版本、插件自身编译版本不能误读为最高支持版本。没有明确上限时先核对官方说明，记录证据缺口，不凭猜测建立上限。
5. 使用精确版本，不使用 `+`、动态范围或 `latest.release`；BOM 管理的依赖继续跟随 BOM。Kotlin Compose/Serialization 编译器插件跟随 Kotlin，编译器插件单独核对兼容要求。

## 范围与配置

- 依赖版本统一在 `gradle/kmp.versions.toml` 维护；同时检查内联插件/库版本、BOM、Gradle Wrapper、构建约定插件和 Xcode 工程。
- Gradle 运行 JDK、编译 toolchain JDK、Kotlin `jvmTarget` 与 Java source/target compatibility 分别评估。JDK 与字节码目标可以不同；相关 Kotlin/Java 任务的字节码级别必须一致。
- 本机工具高于官方支持上限时，先使用已有的受支持安装；没有可用安装则记录环境缺口，不修改全局工具或用超范围版本替代验收。
- Android `compileSdk`、`targetSdk` 和 Build Tools 选择工具链支持的最新正式版本；`minSdk`、iOS deployment target 是支持范围，不因追新自动提高。
- KMP 依赖必须核对 Android、`iosArm64` 和 `iosSimulatorArm64` 工件；不能用 Android 构建成功替代 Native 验证。
- 只修改升级必需的配置和 API，不增加功能、不重构无关代码、不改变既有布局和交互。架构变化同步 `docs/architecture.md`。
- 保留开始升级前的工作区改动，并在记录中区分用户既有修改与本次新增修改。
- 官方范围内的候选 JDK 可下载到已忽略的 `.gradle/jdks/` 做项目内验证：解压目录保留发行版名称和版本，安装包放在系统临时目录；不提交二进制，不改变全局 JDK 注册或系统配置。验证记录注明实际使用路径，清理仍遵守删除授权规则。

## 执行流程

1. 读取 `AGENTS.md`、本规范和测试指南；盘点工作区、已安装 JDK、Android SDK、Xcode 与模拟器环境。
2. 记录当前版本、最新正式版、预览版例外、官方约束、计划采用版本及证据链接。用发布元数据确认工件实际存在，不能只看搜索摘要。
3. 大改动先提交具体方案供 Xander 确认；确认后先更新规则，再修改配置。已经明确授权的范围不反复请求确认。
4. 先升级工具链并验证配置/编译，再按 UI、数据/网络、测试/分析工具分组升级；范围内仍须运行必要回归，但不通过大量试验探索范围外组合。所有 Gradle 调用串行执行。
5. 外部 SDK/API 不兼容先对照官方文档和参考实现；超过两轮未解决换调查策略。确定不兼容的版本记录原因后选兼容版本，不进行无证据试错。
6. 同步 README 环境和版本表；当次清单与结果放在 `docs/audits/YYYY-MM-DD-dependency-upgrade.md`，实施步骤可放在 `docs/superpowers/plans/`。历史记录保留核对时间，不改写为未来验证结果。

## 验证与交付

根据实际升级范围执行 [测试指南](testing/README.md) 的检查。全项目升级至少覆盖：

- Android Debug 构建、代表性 Release R8 打包、Android lint 与有效模块 detekt。
- 所有已有共享逻辑及 Android 宿主测试模块；UI 工具链变化覆盖自适应行为测试。
- iOS Kotlin 编译、iOS 模拟器行为测试和 Native 真实 Entry 调用；偏好控件升级必须覆盖 Preference 初始化。
- Xcode 模拟器整包构建；单独报告 Swift/Xcode 与 Kotlin 验证。
- 实验性 Fused Library 和 Baseline Profile 测试模块的构建；设备运行或 Profile 生成独立记录。

交付清单包含采用/保留版本及理由、实际命令、通过/失败/跳过数量、缓存复用和未验收项。编译、行为测试、截图与设备验收分别报告。不得自动更新正式截图基线；模拟器显示设置修改后按现有规则还原。

## 必须单独授权的操作

升级授权不包含以下红线：删除文件/目录或 git 回滚，修改 `.env`、密钥、token、CI/CD 配置，数据库 schema/数据迁移，安装新全局依赖或修改系统配置，公开发布/生产部署。需要这些操作时先准备具体可审查方案，说明范围，再请求 Xander 授权；不受影响的升级继续进行。
